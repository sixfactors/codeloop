Every board read and write goes through the storage layer

c-320 · codeloop · storage · system design

How codeloop runs on one laptop today: every process, every file it writes, which files git keeps, and where each board storage option would sit.

The problem

Moving ops-ai's board out of its repository put one project's data in two places. The board and its run state now live in ~/.codeloop/projects/ops-ai on one laptop, while the specs, evidence and wiki the board points at stay in git. Git has no copy of ops-ai's board after version 957 (the live board is at 969), so a lost laptop loses every board change since the move. Nothing else should move until this picture is agreed.

Broken or surprising today

  • ops-ai's hourly run --agent has failed every hour since 15 October. Its crontab line is 1,153 characters; cron cuts a command at 1,000, inside a quoted path, so the shell reports an unmatched quote and the run never starts.
  • The hook daemon is unused: codeloop-hook is not on PATH (the global link provides only codeloop), and ops-ai's hooks call codeloop guard directly, one node process per edit, shell command and prompt.
  • The global codeloop links straight to dist/index.js, so the bin/codeloop memory ceiling is never applied, the hub included.
  • codeloop's own repository has no Claude Code, Cursor or git hooks installed. Its board is tracked but last committed on 15 October; 280 board events have been written since.
  • ops-ai's story data is in three places: the board in ~/.codeloop, specs and evidence under .codeloop/, and a tracked evidence/027/ and specs/README.md at the root.
  • The hub registry lists 14 projects; 6 point at deleted temporary folders.

Context

Codeloop has no long-lived engine. Each command, hook and scheduled run is a short node process that reads the project's files, decides, writes and exits. Only the hub, and the hook daemon when it is used, stay up.

Deployment topology

store.layout picks folder names (dotfolder under .codeloop/, or the legacy root layout that codeloop's own repo still uses). store.home picks the disk: repo, the default, or user, which turns each path named in store.move (all of them when the list is absent) into a link into ~/.codeloop/projects/<id>/. store move copies, rewrites store.home, and leaves the original for the person to delete; commands refuse while a real copy sits where a link belongs.

Network view

Everything is on loopback. The hub listens on 127.0.0.1:4050; on loopback the browser is the owner by default. Agents and the SDK send x-codeloop-token, a token kept in ~/.codeloop/state/hub.json with owner-only permissions. Hooks reach hookd over a unix socket with mode 0600. The only outbound call codeloop makes for the board is the hosted board push, which runs only when .codeloop/cloud.json exists; neither project has one.

Tech choices

How concurrent writers are kept safe today. Every board write takes cards.json.lock, created so only one process can hold it, with its pid inside; a waiter gives up after 30 seconds and a lock whose pid is dead or older than 5 minutes is taken over. Under the lock the writer re-reads the file and refuses if the version moved; callers retry up to five times. The new board goes to a temporary file renamed over the old one. state/run.lock lets one turn, scheduled run or store move change the board at a time. Leases stop two sessions editing one story's plan files. None of this controls which commit carries which story's board changes.

Risks

  • ops-ai's board is on one disk with no git copy after version 957. Mitigation: commit a snapshot, or pick an option above that keeps history off the laptop.
  • Eight of the twelve story steps rewrite the whole board file, and the post-commit hook writes it again right after each commit, so a tracked board is never clean and any plain commit sweeps other stories' events.
  • Sessions in one tree share one git index; a plain git commit takes another session's staged files. ops-ai's board-move commit swept a stale dependency list this way and had to be undone. Committing by path is a working rule, not enforced by codeloop.
  • In user mode the code writes every story's files to the main tree even when store.move left specs in the repo, which only matters for a project that builds in worktrees.
  • The hourly unattended run in ops-ai does not run at all until its crontab line is shorter than 1,000 characters.
